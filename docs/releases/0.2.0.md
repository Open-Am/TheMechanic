# 0.2.0

Phase 2 of the brief: the game is playable in a phone browser with placeholder shapes.

## Added

- The game is playable in a phone browser with placeholder shapes: briefing, take parts off, inspect, fix, put back, pull the cord, and a scored result (plan 0003).
- Gestures the owner chose: pull a part along its path to take it off, tap a tray chip to read its card, drag a chip onto the machine to put it back. A blocked pull or put-back shows nothing beyond the same press every touch gets (plan 0003, ADRs 0007, 0011).
- `app` layer: the game controller, timer, action log, events and fault choice without repeats (plan 0003, ADR 0010).
- `render` layer: placeholders from `machine.json` with 44 px hit volumes, an orbit camera with limits, and the ADR 0008 motions on removal and in reverse on install (plan 0003, ADRs 0006, 0008).
- `ui` layer: briefing, HUD, tray, card with the 2 s fix, result screen, and `ui/strings.ts` (plan 0003).
- Local `Clock` and `Audio`; audio stays silent until sounds are recorded (plan 0003).
- Diagnostic overlay with `?diag`, development builds only (plan 0003, ADR 0007).
- `npm run size` checks gzipped JavaScript against the budget: 139.7 KB of 350 KB (plan 0003, ADR 0006).
- `npm run verify:phone` plays every fault in headless Edge or Chrome at 390x844 with real gestures, with no new dependency (plan 0003).
- Each tray chip shows a picture of its part, drawn from the part itself, so it will show the real model in Phase 3. Asked for by the owner after trying the phone build (plan 0003 step 11).
- Design notes: `docs/design/interface.md`, `animation.md`, `diagnostic-mode.md` (plan 0003).
- 156 tests, up from 77. The browser check also confirms every tray picture renders.

## Changed

- `three` and `@types/three` 0.186 added, as approved for Phase 2 in ADR 0002.
- The boundary test now lists which packages each layer may import: only `render` may import `three`, and no layer may import any other package (plan 0003, ADR 0010).
- Platform interfaces moved from `platform/interfaces.ts` to `platform/interfaces/`, as ADR 0010 lays out.
- The orbit camera is written in the project instead of using `OrbitControls`, which cannot hand a drag over to the pull gesture.

## Fixed

- Found by the browser check before release: with four or more chips the tray overflowed sideways and the last chips could not be reached by touch. The tray now wraps onto more rows.

## Known gaps

- The owner played the build on a real phone on 2026-10-10 and wrote "the app yes decent". That was before tray pictures were added.

- The frame rate was measured only in headless Edge with software rendering (118 fps at 4x CPU throttle). That says little about a real low-end phone.
- With the owner's gesture choice, in-place inspection (ADR 0011) has no interface: condition text appears only on the tray card. The rule stays in `core`.
- No share button, daily fault or best scores yet (Phase 4). No GLB loading (Phase 3).
- The stage lighting and placeholder colours are first guesses.
