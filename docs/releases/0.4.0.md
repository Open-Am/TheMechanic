# 0.4.0

Phase 3a: the asset pipeline, and a blocked-out model of the real machine in the game.

## Added

- `npm run assets`: validates the Blender file, exports the GLB, bakes the ground shadow, optimises with glTF Transform (Meshopt geometry, WebP textures), checks the model contract and the budgets, and copies the results into the game. Stops at the first failure (plan 0005, ADRs 0012, 0014).
- Blender tooling in `tools/blender/`: version check and shared helpers, `scaffold.py`, `block.py`, `validate.py`, `export.py`, `bake_ground.py`, `render.py`, `match.py`, `make_env.py`; `tools/run-blender.mjs` finds Blender through `BLENDER` or PATH (plan 0005, ADR 0012).
- `assets/gen950/blend/gen950.blend`, in Git LFS, with a look-development scene that matches the game: the same environment, key light direction and Khronos PBR Neutral tone mapping (plan 0005, ADR 0014).
- A blocked-out model of all 16 objects at real size from the references: 5,832 triangles, 79.8 KB compressed. Every object is `blocked` in `assets/gen950/STATUS.md`, with what still differs; nothing is called finished (plan 0005, ADR 0013).
- Match images: the model beside reference photos from the front right, the back and the front left, made by `tools/blender/match.py`. They contain third-party photos, so they stay local and out of git, like the references (plan 0005, ADR 0013).
- The game loads `model.glb` with the Meshopt decoder from `three`, falls back to a part's placeholder when its node is missing, and uses placeholders throughout when there is no model (plan 0005).
- A real environment map, `game/public/env/workshop.hdr`: Poly Haven's CC0 "Wide Street 02", 512 × 256, 378.6 KB (plan 0005, ADR 0014).
- A ground shadow baked in Blender from the assembled machine, 6 KB (plan 0005, ADR 0014).
- `tools/pipeline/budgets.json` holds the budgets and triangle allocation for both the Python and Node tools.
- The diagnostic overlay shows whether the model, a partial model or placeholders are in use.
- 187 tests, up from 166, including the pipeline checks against deliberately broken models.

## Changed

- `machine.json` placeholders now follow the model's real layout: facing the panel, the recoil starter is on the right and the alternator end on the left, with the cylinder, plug and muffler at the back. Placeholder positions and sizes, and the explode directions of the recoil starter, alternator cover, capacitor, spark plug, plug cap, fuel tap and hose, changed to match. No field or ID changed; the removal order is untouched.
- `@gltf-transform/cli` 4.5.0 added (dev), pinned exactly (ADRs 0002, 0012).
- Each part's materials are copied per part, so fading one part never fades another that shares a material.
- The environment's intensity is set per source: 0.55 for the generated studio, 1.25 for the street HDR.

## Fixed

- Mesh quantization stores each node's geometry with a decoding scale. The first loader reset that scale when a part was reset or pressed, blowing parts up about sixfold. Parts are now wrapped, and only the wrapper is ever scaled. Found by the browser check; a test covers it.

## Known gaps

- The model is blocked out, not modelled: flat colours, simple shapes, no baked detail or wear. Plan 0006 does the realism work.
- Metal parts read too dark against the street environment. Materials and exposure are tuned in plan 0006.
- Fuel tap position, hose route, capacitor look and location are unconfirmed (`docs/open-questions.md`).
- `npm audit` reports a high-severity advisory in `braces`, a dependency of the glTF Transform CLI. It is a build tool and never ships.
- The frame rate was measured only in headless Edge with software rendering: 118 fps at 4x CPU throttle with the model. Not representative of a real low-end phone.
- JavaScript is 174.6 KB gzipped, up 31 KB for the glTF loader and Meshopt decoder, within the 350 KB budget.
