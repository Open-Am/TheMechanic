# 0.18.0

The player can now diagnose before and while taking parts off: six checks from a Check button beside Pull cord, each costing a few seconds of score and patience, each showing what the engine does. A clean job earns a bonus (plan 0019, ADR 0029). Built on branch `plan/0019-diagnosis-and-faults` with release 0.19.0, before plan 0018 (the pull on screen) and without the testers model.

## Added

- **Six checks** (ADR 0029): listen to a pull (3 s), watch the smoke (3 s), read the plug (2 s), spark test (4 s), fuel flow (3 s), volts test (4 s). Each can be done once per round and not after the fix. When a check is possible is data: `machine.json` gains `checks` (`off`, `on`, `allOn`, `tool`), validated for all six, known parts and no contradiction.
- **Clues are fault data.** `faults.json` moves to schema 2: each fault gains `clues`, one line per check, validated (every check, non-empty, no unknown check; a line naming the bad part is a warning). Drafts for the six faults, unverified.
- **Core.** The `check` action with `checkId`; refusals `check_unavailable`, `already_checked`, `already_fixed`; `checksDone` in the round state; `checkPossible`, `unmetNeeds`, `checkSeconds`, `clueText`. Checks cost patience by their seconds (changing ADR 0015's "only a failed pull"). The score is elapsed + 10 per wrong part + 15 per failed pull + the checks' seconds − 10 for a clean job (fixed, no wrong parts, no failed pulls), never below 0; `ScoreBreakdown` gains `checkSeconds` and `clean`.
- **App.** `propose({ type: "check", checkId })`, a `checked` event, `resultOf` (the only path to clue text, tested), `checks()`, `checksPossible()`, `notes()` from the log. Sounds from the existing moments only: the cord, then the failed start or the catch by symptom (listen, smoke, volts), the cord alone (spark), nothing (plug, fuel).
- **Interface.** A Check button on the Pull cord row; the Check sheet with each check's name and cost, greyed with what it needs in words about the visible machine ("Needs the spark plug out", "Needs every part on"), a done check showing its result, "Not needed: you have fixed it." after the fix; the result on the card; the notes ("What you found"); "Checks" and "Clean job" rows on the result screen.
- **Render.** A check that runs the engine presses loose parts home, as a pull does.
- **Diagnostic mode** lists the checks possible now and every result.
- **Text-mode player** checks first and prints every clue.
- **Development only:** `?faults=a,b,c` plays those faults first in free play, so `verify:phone` reaches every fault in one pass.
- Tests: 511, up from 444 (reducer, rules, patience, score, validator, app, ui helpers).

## Changed

- The spark plug's healthy condition reads "Electrodes are sound. The gap is right." (plan 0019 reading 5).
- A perfect play now scores 10 less (the clean bonus). Bests saved before this release were scored without it.

## Fixed

- `npm run play` reported "Some faults did not complete" since release 0.11: its walk-out was scored at 60 s, before any customer leaves. It now scores a second after the walk-out.

## Checked

See release 0.19.0: both were checked together.

## Known gaps

- No tester trip and no check animation: the testers model (`testers.glb`, plan 0019 step 6) and the pull on screen (plan 0018) are not built. Listen and look play only sounds, and "fires and dies" sounds the same as "runs" (the catch); the clue line tells them apart.
- `apply()` keeps its optional customer argument; the round setup with a kit waits for plan 0023.
- Every clue line is an unverified draft (docs/open-questions.md). The owner has not looked on a phone.
